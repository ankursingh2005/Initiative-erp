Project purpose

Bring outlet sales, employee attendance, stock visibility and product profitability into one web application. Teams can upload operational data, review results and download reports for management review.

Monthly Incentives

01 / Sales performance and incentive reporting

Upload monthly outlet sales and review the calculated incentive by outlet, category and reporting group.

Basic calculation

Estimated average profit = Total sales × Profit rate
Base incentive = Estimated average profit × Incentive rate

The default profit rate is 7% and the default incentive rate is 2.5%. Both are configurable. These are estimated incentive inputs, rather than actual product-cost profit.

Illustrative calculationAmount
Monthly salesRs. 100,000.00
Average profit: 100,000 × 7%Rs. 7,000.00
Base incentive: 7,000 × 2.5%Rs. 175.00

Additional report calculations

Exact sales incentive: the calculated base incentive is multiplied by the applied share percentage configured for the outlet / group.

IDS Fund: a separate calculation uses sales multiplied by the configured outlet / category incentive rate, then applies the fund share. Non-sales reporting uses this fund allocation. It does not use the basic 7% / 2.5% formula for every total.

User workflow

  1. Open Monthly Sales & Incentive Report.
  2. Select an Excel workbook (.xlsx / .xlsm) or a readable text-based PDF.
  3. Check the selected rates and upload the file.
  4. Review outlet totals, category breakdowns and the available sales / non-sales reports.
  5. Select SALES, NON SALES or BOTH, then download Excel or PDF.
Review before using the report
Confirm the sales period, outlet names, categories and rate settings. Missing rate or fund configuration can leave totals pending. The basic calculated summary and the exact / fund reports may show different totals because they apply different rules.

Local page route: /incentive.html. Confirm the deployed route when using the live site.

Ageing Stock

02 / Inventory age and branch availability

Review inventory quantities by age group, category, brand, model and branch to identify stock requiring attention.

Input and classification

Use a complete Excel stock-ageing workbook with All Data and the required branch sheets: ALM, HZT, ASH, GNG, VKN and MWH. A genuine .xlsx workbook is the safest input.

Age groups in the reportWhat the number represents
0-60 / 61-90 / 91-150 daysUnits in the selected age bucket
151-180 / 181-365 daysUnits held for longer periods
366 days or moreThe oldest stock bucket

User workflow

  1. Open Ageing Stock Analysis from Home.
  2. An authorized operator uploads the complete workbook using Upload & Process.
  3. Check loaded items, missing-sheet warnings and manual category review messages.
  4. Select categories, brand, item type, model search, branch columns and age groups.
  5. Read the individual branch quantities and Present At.
  6. Use Download Report to export Excel, PDF or an image.

Understand the totals

Item count counts product entries; units counts stock quantities. Closing Qty is the sum of selected age buckets and can include other branches. Selecting a branch mainly changes the displayed columns; check that branch's quantity directly.

Example: 3 units aged 0-60 days + 2 units aged 366+ days
All ages: Closing Qty = 5   |   Oldest bucket only: Closing Qty = 2
Import behaviour
A successful new import replaces the entire previous ageing dataset. The current import includes Nos. items, excludes items matched on PWH / Vault sheets, and can hide rows whose overall and branch ageing quantities disagree. Resolve source differences before relying on totals.

Local page route: /ageing-stock. Stock age comes from the uploaded workbook; opening the page does not refresh the inventory snapshot.

Attendance

03 / GPS and selfie-based attendance records

Employees record one punch-in and one punch-out per day. Administrators review attendance, working duration and saved evidence.

Employee workflow

  1. Open Attendance; check the account, date and assigned outlet.
  2. Allow camera and location access on the secure website.
  3. Ensure today's status is Working, then tap Punch In.
  4. Wait for GPS verification, take a fresh selfie and submit.
  5. Confirm the saved punch-in time.
  6. At departure, repeat the verification and selfie process for Punch Out.
  7. Check both times and download Monthly Attendance when needed.

Location and time rules

Employee groupCurrent source rule
Most employeesAssigned outlet required; allowed radius capped at 100 metres
Service Manager A / B, AC Technician A / B, AC Helper A / B, HRAny-location attendance; GPS accuracy and selfie requirements still apply
Punch timestampsRecorded using server Indian Standard Time

Leave, history and administration

Today's Leave status disables punching. Choosing Working alone does not mark presence. A weekly-off selection repeats on the chosen weekday. These controls are not a future leave approval workflow.

Admin, Owner and HR can review the daily dashboard, employee records and selfies. Available downloads include daily Excel / PDF, monthly Excel and an employee's full available attendance history.

Example: Punch in 10:00 → Punch out 18:30
Recorded elapsed duration = 08:30 hours
Record interpretation
Present means a punch-in exists; verify punch-out separately. Elapsed duration does not establish approved paid hours. If saving times out, refresh and inspect the record before retrying. Report a previous day's missing punch-out to the administrator.

Local page route: /attendance. The role list above follows current main.py; older user guides list fewer exempt roles.

Daily Profitability

04 / Sales, product cost and margin review

Compare sales and product cost by date, category and store. Inspect profitable and loss-making entries and export the selected period.

Calculation and example

Total margin = Total sales - Total cost
Displayed Margin % = (Total margin / Total cost) × 100
Illustrative amountsValue
Source sales / cost, before estimated GST upliftRs. 1,000 / Rs. 800
Dashboard sales / cost, multiplied by 1.18Rs. 1,180 / Rs. 944
Displayed marginRs. 236
Displayed Margin %: 236 / 944 × 10025%

The percentage uses cost as its denominator. If cost is zero, the current calculation returns 0%. Product margin does not include all business expenses such as salary, rent or electricity.

User workflow

  1. Open Daily Profitability.
  2. An authorized uploader imports the complete Busy sales export for the required period.
  3. Check loaded and skipped rows; select start / end dates, category and store.
  4. Review Total Sales, Total Cost, Total Margin, category and store summaries.
  5. Open View Items and check loss-making entries and review notes.
  6. Download Profitability Report or Daily Report.
Compare reports on the same basis
The dashboard and Profitability Report use the application's estimated 18% GST uplift. The Daily Report uses original GST-exclusive amounts. New sales uploads replace records across their earliest-to-latest valid date span, so use a complete export for that entire period.
